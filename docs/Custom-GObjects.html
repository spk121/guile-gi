2.5.5 Defining new GObject classes ¶

Usually any GObjects you use will be created by procedures such as window:new, and those GObject types will have been predefined in the typelib. But, it is possible to make custom GObject object classes using the register-type procedure.

Bear in mind, that while Guile-GI internally uses GOOPS, GObjects implemented in it are not quite as flexible. For instance, you cannot meaningfully redefine a GObject-based type, which you could if you just used GOOPS types. On the other hand, you can make use of the features of the GObject infrastructure, such as signals.

Defining a new GObject class is rather complicated.

Procedure: register-type type-name parent-type [list-of-properties] [list-of-signals] [#:vfuncs overrides] [#:interfaces interfaces] ¶

This procedure creates and returns a new <GType> of a GObject object.

type-name is the string name of the new type. Note, that it will be turned into a symbol internally.

parent-type is the <GType> of the parent class to this class. The parent class needs to be <GObject> or a GObject class that descends from it.

list-of-properties is a list of parameter specifications. These parameter specifications can be created using the param-spec-TYPE methods found in the GObject typelib.

list-of-signals is a list of signal specifications. See GObject Signals.

overrides is a list of pairs (name . procedure) that override virtual functions. name is a symbol or string, such as snapshot or size-allocate, naming a virtual function of parent-type, one of its ancestors, or one of interfaces. procedure takes the instance and then the virtual function’s arguments, and returns its return value and output arguments, as multiple values if there are several. An output argument that the caller allocates, such as the GtkTreeIter of GtkTreeModel’s get-iter or the GValue of its get-value, is not returned: it is passed to procedure, which fills it in. Likewise, what procedure does to the fields of a struct argument, such as the iter that iter-next advances, is seen by the caller. If the virtual function can fail with a GError, a Scheme error raised by procedure becomes that error. GObject’s finalize, constructor, set_property and get_property can’t be overridden.

interfaces is a list of interface classes, such as <GListModel>, for the new type to implement. The parent type must not already implement them.

To then make instances of your custom GObject type, use make.

Each virtual function of a class or interface also has a procedure to call it, named after the class and the virtual function, such as widget:do-snapshot. Its first argument is the class whose implementation to use, then the instance and the virtual function’s arguments. Passing the parent class from inside an override chains up to the parent’s implementation. 

(define <Swatch>
  (register-type "Swatch" <GtkWidget>
    #:vfuncs
    `((snapshot . ,(lambda (self snapshot)
                     (snapshot:append-color snapshot color bounds)))
      (measure . ,(lambda (self orientation for-size)
                    ;; minimum, natural, and their baselines
                    (values 100 200 -1 -1)))
      (unrealize . ,(lambda (self)
                      ;; chain up
                      (widget:do-unrealize <GtkWidget> self))))))

(define <NumberList>
  (register-type "NumberList" <GObject>
    #:interfaces (list <GListModel>)
    #:vfuncs
    `((get-item-type . ,(lambda (self) (get-gtype <GObject>)))
      (get-n-items . ,(lambda (self) (length items)))
      (get-item . ,(lambda (self i) (list-ref items i))))))

A tree model for a GtkTreeView can be written the same way. Its iters are structs that the model fills in to say which row they refer to; here, the row number goes in the user_data field. This model is a flat list; examples/tree-model.scm is a complete GTK 4 program whose model has rows with children. GTK 4 deprecates its tree widgets, so there they have to be loaded by name with load-by-name, or with #:deprecated? #t in use-typelibs. 

(use-modules (system foreign))

(define rows #("one" "two" "three"))

(define (row iter)
  (pointer-address (or (tree-iter:user-data iter) %null-pointer)))

(define (point-at! iter n)
  (tree-iter:set-user-data! iter (make-pointer n))
  (< n (vector-length rows)))

(define <RowModel>
  (register-type "RowModel" <GObject>
    #:interfaces (list <GtkTreeModel>)
    #:vfuncs
    `((get-flags . ,(lambda (self) (list->tree-model-flags '(list-only))))
      (get-n-columns . ,(lambda (self) 1))
      (get-column-type . ,(lambda (self column) G_TYPE_STRING))
      (get-iter . ,(lambda (self iter path)
                     (point-at! iter (s32vector-ref (tree-path:get-indices path) 0))))
      (get-path . ,(lambda (self iter)
                     (tree-path:new-from-indices (s32vector (row iter)))))
      (get-value . ,(lambda (self iter column value)
                      (set! (value G_TYPE_STRING) (vector-ref rows (row iter)))))
      (iter-next . ,(lambda (self iter) (point-at! iter (1+ (row iter)))))
      (iter-children . ,(lambda (self iter parent)
                          (and (not parent) (point-at! iter 0))))
      (iter-has-child . ,(lambda (self iter) #f))
      (iter-n-children . ,(lambda (self iter)
                            (if iter 0 (vector-length rows))))
      (iter-nth-child . ,(lambda (self iter parent n)
                           (and (not parent) (point-at! iter n))))
      (iter-parent . ,(lambda (self iter child) #f)))))
