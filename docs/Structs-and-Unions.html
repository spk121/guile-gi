2.3.3 Structs and Unions ¶

In C, a struct or union is named type of a collection of member objects.

The unions and structs are handled in Guile-GI by creating a GOOPS type that wraps a native pointer. Typically, a library provides methods to operate on structs and unions, and Guile-GI wraps those methods as GOOPS generic functions. If a typelib does not provide an explicit constructor for a struct or union, an empty instance can be created by using make. 

(use-modules (gi))
(use-typelibs ("GLib" "2.0"))
;; Create a new empty <GDate> using 'make'
(write (make <GDate>))
(newline)
;; Create a new <GDate> using a constructor procedure
(define dt (date:new-dmy 1 (symbol->date-month 'january) 2000))
;; Modify the contents of <GDate>
(add-years dt 1)
;; Compute the resulting year
(write (get-year dt))
(newline)

The public fields of structs, unions and objects have getters named after the type and the field, such as rgba:red for the red field of a GdkRGBA. Getters return copies of strings, structs and arrays. Fields of plain data – numbers, booleans, enums, flags, and structs made only of those – can also be set when the typelib allows it, either with set! on the getter or with a setter such as rgba:set-red!. Fields that hold other pointers, such as strings, are read-only, because the typelib does not say who would own a new value. A field gets no getter if a method of its type already has that name, and structs with bitfields, which typelibs describe incorrectly, get no field accessors at all. 

(rgba:red color)              ⇒ 1.0
(set! (rgba:alpha color) 0.5)
(point:x (rect:origin rect))  ; rect:origin returns a copy

Structs that have no GType usually can’t be bound, because Guile-GI can’t know how to copy or free them. A few that GTK, GSK and GDK need are wrapped specially: GskRoundedRect, GskColorStop, GskShadow, GskParseLocation, GtkCssLocation, GdkKeymapKey, GdkTimeCoord, GtkPageRange, GtkRequestedSize, GtkRecentData and GtkPadActionEntry. For each, loading its typelib entry defines its class, a constructor that takes the values of its fields in order, all optional, and a getter and a setter for each field. The library’s functions that take or return these structs work too, as do arrays of them, given as lists or vectors and returned as vectors. These structs are copied when they come from C, so changing one in Scheme does not change the library’s copy. 

(make-color-stop 0.5 red)      ; a <GskColorStop>
(color-stop:offset stop)       ⇒ 0.5
(color-stop:set-offset! stop 0.25)

GdkToplevelSize, GdkDragSurfaceSize and GtkBuildableParseContext are opaque and only valid while the library lends them, for example during a signal. Signal handlers receive them as pointers; pointer->toplevel-size and the like wrap a pointer for the struct’s methods.
