2.5.2 GObject Methods ¶

Guile-GI exports object methods as GOOPS methods in the formats type:method and method, where type is the class on which the method is defined and method is its name. Unbound methods (i.e. functions) are only bound to method.

In either case, the following transformations are made to type and method:

  1. Both type and method are converted to kebab-case.
  2. If the method returns a boolean value and has no output arguments, a ? is appended to its name.
  3. If the method has an input, that is also marked as an output, or a pre-allocated output, a ! is appended to its name. This comes from a Scheme naming convention for “destructive” functions – i.e. functions, which may modify their inputs in-place.

There is one exception to the short format. A method, signal or property whose name is syntax in Guile is bound only as type:method, because the short name would replace that syntax in every module that imports the typelib, and break ordinary code there. Among the libraries of GLib and GTK, these are

begin

the signal of GtkGesture, bound only as gesture:begin;

delay

the method of GSettings, bound only as settings:delay;

export

the methods of GDBusInterfaceSkeleton and GDBusObjectManagerServer, bound only as dbus-interface-skeleton:export? and dbus-object-manager-server:export.

The rule covers whatever is syntax in the running Guile, so the same goes for a method named, say, if, do, case, define or when in another library. The generated documentation of a typelib gives such methods under their one name.

The names of procedures in Guile are not treated this way: a method named format or write is added to a generic function that still does what it did for other arguments. Neither is load, which Guile-GI itself makes a generic function, for loading parts of typelibs. Functions that are not methods have no longer name to fall back on, and are bound whatever they are called.

Use whichever bindings you prefer or alternatively rename them using the #:rename argument to use-modules or use-typelibs respectively. Note that Guile currently warns if a binding is imported from multiple libraries (e.g. both GLib and Gtk), but this should not concern you in most cases, as both internally specialize the same generic method.
